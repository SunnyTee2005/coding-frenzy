# 考場畫面規格（仿真依據）

來源：
- CPE 官方《考生使用手冊》2023/11/28 版的截圖（以下用「圖 x.x.x」標註）
- `CodingFrenzy@CPExam.zip`（2026-08-10 版）中未混淆的設定與範本

這份文件只用文字描述觀察到的版面、標籤與行為。原程式、截圖與反編譯結果只放在本機的 `research/`，不進 repo。
引號內的字串是畫面上的原文，實作時要逐字照抄。

## 0. 整體架構

瘋狂程設有兩種視窗：

- **主畫面**：一個 WinForms 視窗，裡面嵌了 IE WebBrowser。授權、登入、題目列表都是**伺服器送來的 HTML 頁面**，內容來自 `cpe0X.arping.me/cert`。上方有一條 WinForms 工具列。
- **解題視窗**：每題一個 WinForms 視窗，使用 DockPanel Suite（WeifenLuo）排版，編輯器是 Alsing SyntaxBox。右側的「建置測試」面板也是 HTML，由 `FrenzyBat/template.htm` 套版產生。

視覺風格是 Windows 7 Aero / 傳統 WinForms：選單列是淺灰漸層，HTML 頁面用 IE 預設字型（新細明體 / Times New Roman），超連結是藍底線。

## 1. 授權畫面（圖 1.1.1）

- **左側欄**：淺灰底。
  - 最上方是按鈕「同意以下各授權規定」。
  - 下面是一串藍色底線連結：「本軟體授權」「Alsing.SyntaxBox」「WinFormsUI」「HybridDSP」「DotNetFireball」「Watcom C++」「PHP」「Json.Net」。
  - 下方有按鈕「返回考場」。
- **右側**：白底。
  - 大標題「大學程式能力檢定」，粗體、有底線。
  - 小節標題「使用方法」「軟體引用」：粗體，淺灰底、黑框。
  - 各小節下是編號清單。
- 對應的設定值是 `<:軟體名稱>大學程式能力檢定<:>`、`<:軟體型態>檢定<:>`。

### 登入前（圖 1.1.2）

1. **登入框**：外框是一條橫線，裡面依序是：
   - 紅字「(請詳細檢查，切勿填錯，填錯需重領准考單應考。)」，其中「准考單」是藍字。
   - 「(A)身分證字號或護照號碼 [輸入框]」
   - 「(C)准考碼 [輸入框] [確認登入]」
2. **提示列**：黃底紅字的大字框「ALT + TAB」，旁邊是「可以切換不同視窗。」
3. **條列**：
   - 紅色粗體「監考機址：http://…」
   - 「如果此處題目區未能於適當時間顯示題目資訊，請按 **F5** 更新。」（F5 是黃底紅字）
   - 「Java 程式撰寫 請使用 class main，按 ALT+L 選 Java編譯器，CTRL+H 可以觀察雙和範例。」
   - 「Java 程式撰寫 換行 請使用 "\r\n" 不要只使用 "\n"。」
   - 紅色粗體「程式通過繳交，請務必按 [桌面/考生功能/考場成績](這是及時資料)，確認資料是否上傳監考機，確認資料是否有誤。」
4. **題目區**：大字「題目」，下方有一個按鈕狀的框「請先登入系統」。
5. **注意事項**：大標題「大學程式能力檢定(CPE)考生注意事項」，下面是考試時程清單：
   - 考生報到時間：17:30~17:40
   - 考生進行考試環境測試：17:40~18:30
   - 休息與準備：18:30~18:40
   - 正式考試：18:40~21:40
   - 紅字：考生於 18:00 後，不准入場
   - 考生於 19:40 後，始得離場不再考試

### 登入後（圖 1.1.3）

- 登入框換成 2×2 表格，藍色大粗體：「(A) 身分證 | (B) 姓名」「(C) 准考碼 | (D) 認證碼」。
  下方小字「(A:身分證,B:姓名字,C:准考碼,D:認證碼)」。
- **題目區**：
  - 大字「題目」，下方是雙線外框的表格。
  - 第一列是「請慢慢開題!! (點擊之後 請等待!!)」。
  - 下一列是紅色粗體「正式考題 00B」。
  - 每題一列，三欄：「解題」連結 ｜ 題號（例如 `00B1.UVA10019`）｜「看題」連結。
- **依時間顯示的內容**：
  - 18:30 前：顯示練習題。
  - 18:30~18:40：封鎖，看不到題目。
  - 18:40 後：顯示考試題。
  - 題目沒出現時按 F5。

## 3. 解題視窗（圖 1.4.1、1.4.13）

- **視窗標題**：`{題號}評量:{英文題名}`，例如 `00B2.UVA12503評量:Robot Instructions`。標題列左側有小圖示。
- **選單列**：由左到右

| 選單 | 項目（快捷鍵） |
|---|---|
| **正式評判(J)**（粗體，帶紅框） | 按下就跳出確認視窗（見下方） |
| 檔案(F) | 提檔續答(W) Ctrl+W ／ 封卷存檔(S) Ctrl+S ／ 另存新檔(A) Ctrl+N |
| 編輯(P) | 放大字型(B) Ctrl + ／ 縮小字型(S) Ctrl - ／ 預設字型(0) Ctrl 0 ／ 貼上範例(H) Ctrl+H |
| 視窗(V) | 顯示全部(A) ／ 顯示題目(P) Ctrl+P ／ 您的小黑(B) Ctrl+B（停用）／ 標準小黑(T) Ctrl+T（停用）／ 顯示結果(G) Ctrl+G ／ 您的輸出(J) Ctrl+J ／ 正確輸出(K) Ctrl+K |
| 編譯器(L) + 目前選擇，例如「編譯器(L)CCPP:MinGW」 | 見下方的編譯器選單 |
| 編譯測試(D)（有時顯示為 (Q)） | 題目預設測試資料(W) ／ 一組隨機測試資料(E)（停用）／ 十組隨機測試資料(C)（停用）／ 使用自訂測試資料(D) ／ 人工公開測試資料(S) |

- **選單列最右側**：
  - 藍色粗體剩餘時間，格式 `2小時11分33秒`。
  - 🍎 紅蘋果圖示。
  - 綠色進度條：剩餘比例，灰底。

- **編譯器選單**（圖 1.4.10）：
  - 目前選擇的項目打勾。
  - 沒安裝的編譯器顯示為灰色，並帶禁止圖示。
  - 項目格式是 `語言:編譯器名稱(快捷字)`，例如：
    - `MSVC:Microsoft Visual Studio 10.0(0)`
    - `CCPP:MinGW(M)`、`CCPP:WatCom`、`CCPP:C`
    - `JAVA:jdk1.7.0_25(7)`
    - `MSCS:v2.0.50727` …（C#／VB／JS 等，考場上都是灰色）
  - 本專案只做 `CCPP:MinGW` 和 Python。Python 的選單字串推測是 `PYTH:Python39`，**還沒有截圖可以確認**。

- **Dock 版面**（標題列下方）：
  - **左上「題文」面板**：HTML 題目。題名是藍底黃字（或藍底白字）置中的大標題，下方是「The Problem」等小節。
  - **左中編輯器**：
    - 等寬字型、行號、C++ 語法上色，關鍵字藍色、字串紅色、註解綠色。
    - `{}` 區塊有折疊符號 ⊟。
    - 有垂直與水平捲軸。
  - **左下面板**：兩個分頁「您的輸出」「正確輸出」，分頁在底部。輸出內容是有行號的等寬文字。
  - **右側「建置測試(G)」面板**（HTML），由上而下：
    1. **個資表**：「(A) 身分證 (B) 姓名 / (C) 准考碼 (D) 認證碼」，藍色大粗體，有框。
    2. **評判狀態鈕**，旁邊是統計文字「59詞，280字元。」。狀態鈕有三種：
       - 「未評判」：淡綠底、藍框。
       - 「通過」：紅底黃字。
       - 「未通過暗中測資」：黑底黃字。
    3. **最近一次測試結果**，格式 `{次數}:{狀態}`，例如「2:CORRECT」「7:WRONG-ANSWER」。外框是雙線；CORRECT 是藍字，其他狀態是紅字。
    4. 「題目資料」鈕，加上 `(13B1.UVA10019) Funny Encryption Method :`。
    5. 「語法規範」：藍底黃字，點開看編譯訊息。「語量規範(0)」：藍底黃字，顯示禁用語法的數量。
    6. 「語意檢測」鈕，加上「輸入區放大」「輸入區縮小」。
    7. 「標準輸入串」輸入框，自訂測資時可以編輯。
    8. **對照表**：
       - 「您的輸出串 | 正確輸出串」左右並排，換行處顯示 `↵`。
       - 「您的錯誤串 | 正確錯誤串」
       - 「您的耗時(GCS) | 標準耗時(GCS)」，例如 0.238120 / 0.141628。

- **正式評判確認視窗**（圖 1.4.2）：
  - 標題「批改確認」。
  - 內文「批改錯誤將罰扣20分鐘，您確定要批改嗎?」，左邊有問號圖示。
  - 按鈕「是(Y)」（預設）、「否(N)」。
- **另存新檔**（圖 1.4.5）：
  - 小對話框，提示「請輸入檔名」，下方是輸入框。
  - 按鈕「取消」「確認」。
- **提檔續答**（圖 1.4.6）：
  - 清單項目的格式是 `CPE_TEST-(18;58;50)-{guid}@{md5}@main.cpp`。
  - 按鈕「取消」「確認」。
- **封卷存檔**（圖 1.4.7）：
  - 自動用時間加隨機檔名存檔，項目格式是 `(14-59-26){guid}@{md5}@main.cpp`。
  - 存檔後可以在「提檔續答」裡選回來。
- **貼上範例**（Ctrl+H）：
  - 在程式碼最後面插入註解區塊，開頭是 `//== 以上為雙和範例`。
  - 範例內容是 a+b 的 C++ 程式，加上 Java 版本，都包在 `/* … */` 裡。
- **換題續答**：關閉或縮小解題視窗，就會回到主畫面的題目列表。

## 4. 成績表（圖 1.2.4）

- **視窗標題**：「聯賽成績(限網：http://…)」。
- **選單**：「上一頁(B) 下一頁(N) 更新(R) 搜尋(S) 搜尋下一個(D)」。
- **標頭列**：深灰底白字，例如「(點選標題可排序) 這是來自 cpe01.arping.me 分站 於 2014/03/18 18:50:46 的整合性資料。本表 5分鐘 內會更新一次，請耐心等待!! 必要時 請更新瀏覽一次。」
- **表格欄位**：「序 | 學校 | 暱稱 | 解題 | 耗時 | 每題一欄（00B1.UVA10019 …）| 身分證 | 複准 | 准考碼-認證碼」。
  - 標題列是黃色漸層，下一列是每欄的篩選輸入框。
- **每題儲存格**：
  - 格式是 `嘗試次數(分鐘+罰時)`，例如 `1(0+0)`、`2(3+20)`、`3(3+40)`。
  - 底色：答對是綠色；答錯是粉紅，例如 `1(0+20)`；沒交是米白，例如 `0(0+0)`。
- 「耗時」只加總答對的題目，例如解 5 題、兩題錯誤，總和仍是 17 分。
- 表格每 5 分鐘更新一次。

## 5. 結果狀態（手冊 1.5 表）

| 字串 | 意義 |
|---|---|
| COMPILER-ERROR | 程式碼未通過編譯（點連結看錯誤訊息） |
| CORRECT | 正確 |
| NO-OUTPUT | 沒有輸出 |
| PENDING | 處理中 |
| PRESENTATION-ERROR | 結果正確但格式錯（多或少空格、換行） |
| RUN-ERROR | 執行時發生錯誤 |
| TIMELIMIT | 超過時間限制 |
| WRONG-ANSWER | 答案錯誤（格式錯太多也可能是這個） |

## 6. 編譯 / 執行指令（`FrenzyBat/frenzybat-*.bat`）

- **CCPP:MinGW**：
  ```
  g++.exe -O2 -lm -static-libgcc -static-libstdc++ -Wl,-Bstatic -lstdc++ -m32 -omain.exe main.cpp
  ```
  - **C 和 C++ 共用這個選項**：原始碼一律存成 `main.cpp`，用 g++ 編譯，所以 C 程式其實是用 C++ 規則編譯。
  - 沒有 `-std`，MinGW GCC 6.3 的預設是 gnu++14。
  - `-m32` 代表編出 32 位元程式。Windows 上 `long` 本來就是 32 位元，Mac / Linux 則是 64 位元。
- **PYTH**：
  - **沒有編譯步驟**（`Com=echo`），直接執行 `python main.py`。語法錯誤會在執行時出現。
  - Python 的路徑從 `%LOCALAPPDATA%\Programs\Python\{版本資料夾}` 等位置尋找。
- **MSVC**：`cl.exe /O2 /EHsc main.cpp`。
- **流程**：
  - 學生程式在 `stu/`、標準解在 `ans/`，兩邊各自編譯、執行。
  - 再由 `frenzybat.exe score` 比對輸出，結果寫入 `out.acm.txt` 等檔案。
  - 耗時以 GCS（gigacycles）表示。
